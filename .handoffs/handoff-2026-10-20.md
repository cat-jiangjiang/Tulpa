### 具体改动清单

#### A. 桌面黑框：沙箱注入杀死 QQ（根因结案）

- 现象：桌面每 20~40 秒弹一个 `QQ has stopped working` 黑框，QQ.exe 越攒越多。
- 根因：代理沙箱给每个子进程注入 `<WorkBuddy 安装目录>\resources\app.asar.unpacked\cli\vendor\sandbox\<版本>\tsbx.dll`。注入沿 `up.py -> supervisor -> watchdog -> NapCatWinBootMain -> QQ` 一路继承，QQ 约 20 秒后以 `0xC06D007F`（delay-load 的 `ERROR_PROC_NOT_FOUND`）自杀。最近 12 份 WER 崩溃报告的 `LoadedModule` 全部含该 DLL。
- 排除项：自己写的 PE 解析器（`.tmp/pe_delay.py`）验证 QQ.exe / QQNT.dll / 三个原生 `.node` 的延迟导入全部可解析，所以不是缺文件，是运行时 `GetProcAddress` 被 hook 破坏。
- 沙箱配置绕不过：正确 key 是 `sandbox.allowUnsandboxedCommands`，但 `app.asar` 的 `ensureHostEndpoint` 硬编码 `sandbox.allowUnsandboxedCommands=false (product policy)`；`dangerouslyDisableSandbox` / `excludedCommands` 在 asar 里 0 次命中。
- 解法：`water-group/start-bot.pyw`。`.pyw` 关联 `pythonw.exe`（无控制台），由 `explorer.exe` 代启动，父进程是 explorer，既不继承注入也不在代理的 job 对象里。
  - `ShellExecuteW` 不行：对 .exe 内部仍走 CreateProcess，实测 `parent=python tsbx_count=1`。
  - `.vbs` 不行：`explorer.exe x.vbs` 打开的是所在文件夹。
- 配套：`bootstrap.sandbox_dll()` 用 `GetModuleHandleW("tsbx.dll")` 自检；`watchdog.py` 启动时若带注入会打 WARN；`up.py --stop` 用 `taskkill /F /T /PID` 退整栈。
- 验证：换栈后 5 分钟守护日志零新增、崩溃弹窗 0 个、`18:56` 之后 QQ.exe 崩溃 0 次。

#### B. 监听：只活一轮，必须重挂

- `listen.py` 是唯一把「有人 @」变成「叫醒 agent」的进程，且设计上 WAKE 就退出（让 agent 观察到完成事件）。
- 事故：会话中断 / 栈重启 / 上下文压缩后没人重挂，消息照落 `wg_events.jsonl` 但没人叫醒，表现为「发了消息没反应」。
- 修法：`up.listener_pids()` 匹配 `daemon/listen.py`，`up.py --status` 直接显示「监听 : 未挂 —— 消息照收，但没人会叫醒你」。

#### C. 按花名 @ 人

`water-group/daemon/reply.py` 新增：

- `AT_TOKEN = re.compile(r"@\{([^{}\n]{1,24})\}")`：只有写在花括号里的名字才算 @。群里正文的「@时月」是普通文字，真正的 @ 是消息段。
- `group_members(group_id)`：走 OneBot `get_group_member_list`，进程内用 `_ROSTER` 记忆化。
- `resolve_member(name, group_id)`：四层解析，精确优先。
  1. 纯数字当 QQ（唯一不会歧义的输入）
  2. 本群名片 / 昵称精确
  3. 档案（主名 / 别名）精确
  4. 本群名片近似 -> 档案近似（单字不做近似）

  名片排在档案前面：群里最直白的称呼是名片（`时之锁-肠宝盒`、`坏乖😋`），档案兜住改名前的老叫法（`孩董` -> criss、`领导` -> 时月）。**同名报候选，不猜**：`--who momo` 列出 3 个 momo，`--who 时之` 列出两张撞车名片。解析失败降级成文字照发，不拒发。`@{🐟包}` 判为「是我自己」。
- `build_segments(text, group_id, leading=())`：把 `@{花名}` 换成 `{"type":"at","data":{"qq":...}}`；`_tidy()` 合并相邻 text 段。
- `onebot_send(group_id, segments, message_id)`：带 at 段时**强制走 OneBot**。`send_chat_reply` 只吃纯文本，会把 at 静默降级成文字；OneBot 不可用时直接 `SEND_FAILED`。
- 命令行：`@{花名}`（正文内）、`--at 花名`（可重复）、`--who 花名`（只解析不发）。

`water-group/memory_engine.py`：把 `find_profile` 的匹配拆成 `match_profiles(identifier)`，返回 `(exact, loose)` 全集；`find_profile` 改为取 `(exact or loose or [None])[0]`，语义不变。原因：「时之」同时是 `时月` 和 `时之锁-肠宝盒` 的子串，只取第一个等于静默替用户选人。新增模块级 `GENERIC_ALIASES = ("领导", "群友")`。

真实发送验证：回 `id=1516`，`get_msg` 回读 `[CQ:reply,id=1624835236][CQ:at,qq=843372773] 学废了`；回 `id=1533` 时 `@{孩董}` 走档案别名命中 `2057796208`。

#### D. 连发的 @ 被一条回复吞掉（本次最重要的缺陷）

- 事故：`1563`（「？」）和 `1564`（「@一下地牢主」）相隔 30 秒。回 1563 的那条消息落在 1564 之后，`up.replied_after` 的兜底规则「这条之后只要出现过自己的消息就算回过」把 1564 判成已回。于是 `--list` 显示 `[已回]`、`watch.py` 从 `fresh` 里滤掉，群里表现为「@ 了没反应」。账本 `wg_replied.jsonl` 里根本没有 1564。
- 修法：`up.ledger_started()` 读 `wg_replied.jsonl` 首条 `ts`（按 mtime 缓存），`replied_after` 对**比它新**的事件只认账本，兜底仅对账本建立之前的老消息生效。真实账本起点 `15:36:08`。
- 回归测试：`scripts/check_wake_ledger.py`，四条断言（老消息靠兜底 / 账本期内不许被自己的消息洗白 / 更后面那条同样不许 / 账本里明确记过就是已回）。
- 配套一：`reply.py --wait N` 发完就地进等待（`listen.py --timeout N --cycles 1 --no-digest`），空窗从「一整轮 agent 思考」压到几百毫秒。已有监听在跑时跳过，不会挂两个。
- 配套二：`listen.py --no-digest`。不加这个开关时，超时后会跑 `dossier.py --digest`，积压时实测 62 秒，把「等 6 秒」拖成一分钟，等待不再可预期。
- 配套三：`reply.py --also ID`（可重复），一条回复顺带记多条账。发送前若发现更新的待回，打印 `NOTE 后面还有 N 条在等：<ids>`。

#### E. `--wait` 前台被超时砍掉

- 实测：前台跑 `--wait 180`，工具超时把进程组 SIGTERM 掉；消息其实已经发出，但 stdout 走管道是块缓冲，连 `SENT` 一起被吞，看起来像没发。
- 修法：`sys.stdout.reconfigure(encoding="utf-8", line_buffering=True)`；规则里写明 `--wait` 要放后台跑（`run_in_background`）。

#### F. 冷启动入口：AGENTS.md 曾指向会杀死 QQ 的那条路

- 问题：`AGENTS.md` §6.1 教的是 `uv run python water-group/bootstrap.py`。新 Agent 接手时照着做，会从沙箱里起栈，`tsbx.dll` 一路继承到 QQ，二十秒崩溃循环原样重建。
- 修法一：`AGENTS.md` 新增 **§0 接管水群**，放在文件最前面（项目上下文注入会截断长文，§6 往往读不到）。给出 explorer 代启动命令、起好之后的四条日常命令、以及「动手前读 `.agents/rules/water_group.md`」。
- 修法二：`AGENTS.md` §6.1 改写为 `start-bot.pyw` 优先，`bootstrap.py` 降级为只读自检。
- 修法三：`water-group/bootstrap.py` 加硬拦截。检测到 `sandbox_dll()` 非空且不是 `--status-only` / `--allow-injected` 时打印原因并 `return 2`；顺带把结尾的 `main()` 改成 `sys.exit(main())`（否则返回码被丢掉，永远 exit 0），并让 `--status-only` 在打完三行检查后真的提前返回（原来会继续跑群列表同步，还会打印一段让 Agent 去用 `wait_chat_messages` 的过时指南）。

## 4. 项目约定参考

- 包管理器：Python 一律 `uv`（`uv run python ...`），禁止 `pip`；Node 脚本零依赖直跑，确需依赖用 `pnpm`，禁止 `npm` / `yarn`。
- 导入：水群模块统一 `import water_group...`；严禁把连字符目录 `water-group/` 加入 `sys.path`（同一文件以两个名字加载会拆状态）。
- 进程安全：禁止 `taskkill /F /IM python.exe` 之类通配杀进程；宿主机官方 QQ（账号 `1716200584`）绝对不可终止；端口清理走 `netstat -ano | findstr :<port>` -> `tasklist /FI "PID eq <pid>"` -> `taskkill /F /PID`。
- 提交：约定式提交；`git add <file>` 逐个暂存，禁止 `git add .`；commit 前跑 `uv run python scripts/check_publication.py`。
- 隐私：`.env`、`water-group/config.json`、`water-group/status.json`、真实人设卡（`*yu_bao*`）、`data/`、`imports/`、`reports/`、`tools/` 均在 `.gitignore` 内，严禁提交。
- 群友记忆：只通过 `query_member_dossier` / `update_member_dossier` / `consolidate_chat_memory` 维护，**不要直连 SQLite**。`traits` 必须传 dict，传数组会被静默丢成空。
- 写作口径：1~10 字短句、打字感、不换行、最多两条；禁客服腔、禁排比升华、禁括号内心戏。引用不通知被引用的人，只有 @ 会响，所以回谁就只引用谁，要叫人出来才 @，一条最多 @ 两个。

### 注意事项

- `--wait` 必须放后台（`run_in_background`）。前台工具调用有 120 秒上限，超时会把进程组 SIGTERM 掉。
