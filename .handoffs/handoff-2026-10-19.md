# Handoff 交接文档 (2026-10-19)

## 1. 项目概述

- **项目名称**: Tulpa
- **项目类型**: 桌面与终端 AI Agent 本地知识库、QQ/微信数据接入网关与 OneBot 11 聊天群交互中间件 (支持 Model Context Protocol / MCP)
- **技术栈**: Python 3.12+ / 3.13、FastMCP、FastAPI、Gradio (管理端)、SQLite (APSW)、OneBot 11 协议适配层
- **Python 包管理器**: uv (强制使用 uv，严禁使用 pip)
- **前端架构**: 原生 JavaScript + HTML5 + CSS3 (位于 web/ 目录，轻量无打包直出)
- **一句话说明**: 把 QQ 与微信资料接入各类桌面 Agent，并通过 OneBot 11 和 MCP 让 Agent 以自定义人格、动态记忆和精准成员画像参与 QQ 群聊交互。

### 具体改动清单

#### 1. 水群一键后台启动引擎 (`water-group/bootstrap.py`, `water-group/sync_groups.py`)
- **修改文件**: `water-group/bootstrap.py`, `water-group/sync_groups.py`, `water-group/config.example.json`
- **改动内容**: 
  - 编写 `bootstrap.py`，支持 `uv run python water-group/bootstrap.py [--status-only]` 一键自检与启动。
  - 自动检测并验证 OneBot HTTP/WS 连接、拉取机器人所在群聊、校验人格卡有效性、初始化群记忆数据库。
  - 自动生成标准化 `BOOTSTRAP_RESULT` JSON 结构，使后续接入的 Agent 零探索、秒级接管水群循环。
- **设计决策**: 避免 Agent 每次开局都调用大量网络与文件工具盲目探测环境，通过单一脚本沉淀确定性流程。

#### 2. 连续发言消息丢弃与竞争状态修复 (`chatlocal/mcp_chat.py`)
- **修改文件**: `chatlocal/mcp_chat.py`, `scripts/check_mcp_chat_turns.py`
- **改动内容**: 
  - 解决群友连续发送消息时，前一条已生成或正在排队的回复因批次游标刷新被误判为过期 (stale) 并被静默取消的 Bug。
  - 改进批次失效逻辑，在同群其他群友插话或连续点名时，只要上下文语义未产生破坏性冲突，保护既有回复队列正常发送。
- **设计决策**: 保障高并发群聊场景下的回复交付率，防止机器人出现漏回、吞话现象。

#### 3. 动态群友小本本记忆引擎 (`water-group/memory_engine.py`)
- **修改文件**: `water-group/memory_engine.py`, `scripts/check_group_memory.py`
- **改动内容**:
  - 创建 SQLite WAL 模式数据库 (`data/group_memories.sqlite3`)，包含 `member_profiles` 与 `member_events` 核心表。
  - **三源数据采集**:
    1. 显式调侃指令: 匹配用户打闹命令 (如 `@机器人 记在小本本上 [某人] 其实 [喜好/事实]`)，实时写入并更新核心槽位。
    2. 直接交互捎带提取: 当机器人被提及或参与对话时，异步捎带分析发言者的语气偏好并记录。
    3. 空闲摘要提取: 群静默或拉取消息等待期间，轻量批处理消化最近发言，沉淀画像。
  - **两层存储架构**:
    1. Tier 1 (L1 Context): 生成超精简群友画像卡 (~80 tokens)，在发言时动态注入模型上下文。
    2. Tier 2 (L2 DB): 结构化持久化详细事件轴与槽位属性，提供 `query_member_dossier` MCP 工具供深度调取。
  - **测试套件**: 编写 `scripts/check_group_memory.py`，覆盖 9 项核心测试并全绿。
- **设计决策**: 兼顾上下文长度预算 (Token Budget) 与长久记忆沉淀，既不臃肿爆 token，又能精准调侃群友黑料。

#### 4. QQ 原生引用回复与称谓机制 (`chatlocal/mcp_chat.py`, `water-group/config.example.json`)
- **修改文件**: `chatlocal/mcp_chat.py`, `scripts/check_mcp_chat_turns.py`, `water-group/config.example.json`
- **改动内容**:
  - 在 `send_chat_reply` 与 OneBot 消息适配层中，原生支持 `reply:message_id` 消息段构建。
  - 支持群内直接引用目标发言气泡，并根据 `reply_style` 配置选择原生引用、纯文本 @、或兼备的称谓模式。
- **设计决策**: 原生引用能让群友通过手机 QQ 点击直接跳转至被引用的历史上下文，体验显著优于生硬的纯文本 @。

#### 5. 群成员号码与名片映射机制 (`water-group/memory_engine.py`, `water-group/sync_groups.py`, `water-group/bootstrap.py`)
- **修改文件**: `water-group/memory_engine.py`, `water-group/sync_groups.py`, `water-group/bootstrap.py`, `.agent/skills/water-group/SKILL.md`
- **改动内容**:
  - 实现 `sync_member_mappings(mappings)`: 通过 `config.json` 中的 `member_mappings`，将 QQ 账号与人名、外号、角色、喜好强绑定，自动合并迁移已存在的 `seed:` 孤儿画像与事件历史。
  - 实现 `sync_onebot_members(members)`: 通过 OneBot `get_group_member_list` 接口获取所有群成员的实时名片与昵称，批量补充进对应成员的 `aliases` 列表。
  - 增强显式指令解析: 支持 `@机器人 标注/认认/绑定 <QQ/@> 是 <人名> (<角色>)`，群聊中可随手为机器人认亲。
  - 升级 L1 上下文卡: 输出格式增强为 `【群友档案：<人名> (QQ: <uid> / 名片: <card>)】外号: ... 喜好: ...`。
- **设计决策**: 彻底解决群友频繁更换个性群名片 (如换成梗名) 导致系统当成陌生新人、无法关联既有种子记忆的问题。

## 4. 项目约定参考

### 环境与工具链规范
- **Python 包管理**: 全项目严格强制使用 `uv` 进行环境与依赖管理，严禁使用 `pip`。
- **Node.js 包管理**: 若涉及 Node.js 项目组件，严格强制使用 `pnpm`，严禁使用 `npm` 或 `yarn`。
- **进程管理安全准则**: 
  - 严禁使用任何形式的通配符杀进程命令 (如 `taskkill /F /IM node.exe` 或 `python.exe`)。
  - 宿主机运行中的官方 QQ 桌面端 (PID 1720 / 账号 1716200584) 严禁终止。
  - 端口清理必须按三步执行: 1. `netstat -ano` 查 PID -> 2. `tasklist` 验证进程属性 -> 3. 确认非 Agent 与系统关键进程后精准终止。

### 架构与代码设计规范
- **单一职责与 DRY 原则**: 逻辑解耦于独立文件，跨模块共享逻辑必须抽离至工具模块，坚决杜绝代码重复。
- **文件写入安全规范**: 严禁使用 Shell 管道或重定向 (`>`、`echo`) 写入代码文件，必须使用专用编辑与写入工具。
- **代码生成规范**: Python 字符串换行统一使用转义字符，Windows 路径必须使用 raw strings。
- **数据库规范**: 数据文件统一置于 `data/` 目录，SQLite 统一开启 WAL (Write-Ahead Logging) 模式与外键约束。

### 敏感信息与安全门禁
- **严禁提交敏感文件**: `water-group/config.json` 与真实人设卡 `water-group/personas/yu_bao.md` 必须被 `.gitignore` 保护，严禁提交推送至远端。
- **代码安全扫描**: 任何 commit 提交前必须执行并通过 `uv run python scripts/check_publication.py` 扫描。
- **提交规范**: 遵循约定式提交规范，逐个文件执行 `git add <file>`，禁止使用 `git add .`。
